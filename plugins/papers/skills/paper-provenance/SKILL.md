# Paper provenance

A reader, or you next month, should be able to take any number or fact in the paper and follow it
to where it came from. In a LaTeX paper, computed results reach the page from code: a script writes
them to `paper/numbers.tex`, with the source of each noted beside it, and the text uses their names.
Everything else is recorded in `paper/provenance.tsv`. A script fails if a number has neither, if a
result was typed, or if the code no longer gives what the paper prints.

## Generated numbers

Do this for every computed result in a `.tex` manuscript. One script, `scripts/paper_numbers.py`
(not `numbers.py`, which hides a Python module that `statistics` needs), reads the stored results, computes each number and prints the whole file:

```python
acc = mean_accuracy("results/run-2/metrics.csv", "ours")     # your calculation
print("% generated by: python3 scripts/paper_numbers.py")
print(rf"\newcommand{{\accOurs}}{{{acc:.2f}\%}} % source: results/run-2/metrics.csv: mean of accuracy, ours")
```

Write it with `python3 scripts/paper_numbers.py > paper/numbers.tex`, put `\input{numbers}` in the preamble,
and write `\accOurs{}` in the text. Command names take letters only, no digits.

- The first line of a generated file is `% generated by: COMMAND`, run from the project root. It must
  print the file rather than write it.
- Each number has a `% source:` note on its own line: the project file it is computed from, then a
  colon and how. Several files are separated by `;`.
- A generated table is a `.tex` file made the same way and brought in with `\input`. It has a
  `% source:` line of its own near the top, which covers all its numbers.
- Change a number by changing the data or the script and regenerating. Never edit a generated file.

Generated numbers need no row in the record. The check reruns each command and compares the output
with the file, so a stale or hand-edited number fails.

These stay typed, with a row: numbers from other papers (`citation`), settings you chose (`exempt`,
or a `file` row with a reason), and every number in a Markdown manuscript, which has no named numbers.
A computed result may be typed in a `.tex` manuscript only with a reason in the row's `typed` column,
for example a value inside a figure caption that LaTeX cannot expand. Generating it is the default;
a reason is not a shortcut.

## The record

Tab-separated, with this header. No quoting: a cell cannot contain a tab.

```
text	value	kind	source	typed
```

| Column | Meaning |
|---|---|
| `text` | Words copied exactly from the manuscript that contain the number or state the fact. LaTeX stays as written (`87.79\%`). Copy enough to identify this occurrence; the sentence fragment, not the number alone. |
| `value` | The number as printed. Empty for a fact with no number. `*` for every number in the text, or in the whole table when the text is inside one. |
| `kind` | `calculation`, `file`, `citation` or `exempt`. |
| `source` | Depends on the kind, below. |
| `typed` | Optional. The reason, in words, a computed number in a `.tex` manuscript is typed. |

- `calculation`: a command, run from the project root, that prints the number in the units printed
  in the paper, and that names a project file (`python3 scripts/stats.py mean-ours`). It must
  recompute from stored results rather than print a saved value. The number is compared at the
  printed precision.
- `file`: a path relative to the project root that holds the value. Use it for a value stated
  directly in a results or data file, and for whole tables with `*`, where every cell is checked
  against the file.
- `citation`: the citation key, optionally followed by a colon and where in the paper
  (`he2016: section 4.2`). Use it for facts and for numbers taken from other papers.
- `exempt`: the reason in words, for numbers that are not results, such as `stride of 2` with
  `architecture setting chosen by us`. Do not use it for results.

```
Our method reached 87.79\% accuracy	87.79\%	calculation	python3 scripts/stats.py mean-ours
Scores by method	*	file	results/run-2/table1.csv	journal template needs a hand-set table
They report a 3.57\% error	3.57\%	citation	he2016: section 4.2
We used a stride of 2	2	exempt	architecture setting chosen by us
worse than that of their 110-layer network		citation	he2016: section 4.2
```

## While writing

Add the number to the script, or the row to the record, in the same edit as the sentence. Never copy
a number from the conversation. In Markdown, write the number from the calculation and record that
calculation. A number with no route goes back to the author rather than into the paper: leave it out
or mark it in the text for them.

Facts have no digits for a script to find. Give every factual sentence that is not common knowledge
in the field a citation in the text and a `citation` row, and check the sentence against the
cited paper's text (not its abstract) before recording it.

## Before sharing or submitting

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/check_provenance.py" paper/main.tex --ledger paper/provenance.tsv --root . --bib paper/refs.bib
```

The commands in the record run with the shell, so read a record you did not write before running
it, or pass `--no-run` to check everything else. Exit code 0 means every digit-written number has a
record or comes from a generated file, and all of them hold. On failure, fix the paper or the calculation. Never edit a number to
make the check pass without finding out which side is wrong, and never add an `exempt` row for a
result.

Then:

1. `--sentences` lists sentences with no citation and no record. Read them and decide which state
   facts that need a source.
2. Warnings list number words ("five seeds"). Record those that are results.
3. Run `papers:reference-verifier` for the references, and `papers:claim-fact-checker` on the claims
   that matter most.

## Limits

Say these when reporting a pass.

- It scans digit-written numbers in prose, tables, captions, footnotes, inline maths, `\input` files
  and macro definitions. It does not scan display equations, code, comments or front matter, so a
  result stated only there needs a row added by hand.
- It checks that a generated file is what its command prints now, and that each calculation gives
  the printed number. It refuses a decimal value written into the generator itself. It cannot show
  that the command uses its source files properly, or that the analysis is right, and a value kept
  in another file the generator reads would pass.
- It trusts the kind a row states, so a result recorded as `exempt` escapes the rule. Read the
  `exempt` and `typed` rows when you report a pass.
- For a citation it checks the key, and that the manuscript cites it. Whether the source supports
  the sentence is a judgement: `claim-fact-checker` tests it.
- It refuses records reading `_ARCHIVE`, and calculations on a `results/<run>` with no `MANIFEST.txt`.
